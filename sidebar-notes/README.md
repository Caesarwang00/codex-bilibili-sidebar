# 侧栏便笺与视频预览

一个本地运行、可以放在 Codex 右侧浏览器里的小播放器。深色界面，标题为「便笺」，可记事并保存在当前浏览器的本地存储。

## 打开

1. 双击 `start.cmd`，或在此目录运行 `node launch.mjs`。
2. 在 Codex 内置浏览器打开 `http://127.0.0.1:17329/`。也可直接让 Codex「在右侧浏览器打开 http://127.0.0.1:17329/」。
3. 首次点「账号 → 扫码登录」，用手机 B 站 App 扫码并确认。登录成功后默认加载账号的「为你推荐」，并加密记住登录；下次打开或重启服务时自动恢复。
4. 点「开始浏览」，视频在上方，操作按钮在下方。用「上一条 / 下一条」连续切换，也可以展开本批目录直接选择。需要公开列表时可手动切到「综合热门」。
5. 自选视频时，展开「粘贴链接」，输入完整视频链接或 BV 号。

服务只监听本机回环地址，不需要安装浏览器扩展，没有开机启动。二维码使用本地 qrcode 库生成，不发送给外部二维码服务。项目已安装依赖；复制到其他机器时需使用 pnpm install --frozen-lockfile 安装。保持服务运行时即可在 Codex 中使用。双击 `stop.cmd` 或执行 `node launch.mjs stop` 停止服务。

## 收起

- **Ctrl＋Shift＋B**：Codex 自带快捷键，收起/显示右侧浏览器面板。全屏浏览器模式下会先回到分栏模式。这个动作不承诺暂停视频。
- **「下一条」上方的整行「专注」按钮**：隐藏视频区域，只留下实际可编辑的便笺。
- **F8 / Esc**：页面内快捷键，和按钮相同。焦点在跨域视频 iframe、聊天框或其他应用中时，不保证收到这些按键；此时用面板按钮或 Codex 快捷键。
- 专注模式只设置区域隐藏，不主动暂停或卸载播放器。点击顶部「资料」返回同一个播放器。后台播放是否持续仍取决于浏览器的后台策略。
- 切换到其他浏览器标签时，页面若收到 `visibilitychange` 隐藏事件，也会收起播放器。
- **向下滚动**：播放器不固定在顶部。下半页是便笺、待办清单、草稿区和 Markdown 参考，滚动后播放器自然移出视野。清单与草稿也在本机保存。滚动本身不暂停播放。

## 支持与限制

### 连续浏览

默认使用扫码登录账号请求 B 站 Web 首页推荐，并按接口要求添加 WBI 签名。只有 nav 接口验证为已登录后才发送账号推荐请求；推荐失败时显示错误，不会悄悄降级为热门。也可手动选择免登录的综合热门。到达列表末尾时继续获取下一页，「换一批」请求下一批。下一条尝试静音自动播放；浏览器拦截时需要点击播放器。滚轮保持普通页面滚动。每周必看接口返回 -352，当前未提供该栏目。

热门列表在本地服务内存中缓存两分钟；个人推荐按当前账号会话分开缓存，最多保留十二批。服务只访问固定的 B 站官方登录与推荐接口，不提供任意网址代理。接口变更、限流或需要验证码时会显示错误，不尝试绕过验证，并保留粘贴链接入口。

### 账号登录

首次点击「账号 → 扫码登录」。二维码来自 passport.bilibili.com，用手机 B 站 App 扫码并确认。页面支持等待扫码、等待手机确认、过期与重试状态，登录后显示昵称和「已记住登录」。未放置退出登录按钮；关闭本地服务会释放内存，保留已加密保存的登录。

登录凭据使用 Windows DPAPI 的 CurrentUser 范围加密，保存于 `%LOCALAPPDATA%\SidebarNotes\bilibili-session.dpapi`。不写明文凭据，不放进浏览器 localStorage、不返回给网页脚本，也不输出日志。加密/解密通过隐藏的 PowerShell 子进程和私有管道执行，命令行参数不包含凭据。文件不在项目目录内，不会随项目源代码提交。

下次启动会解密并先向 B 站校验，成功后才恢复个性化推荐和高清播放。B 站登录失效或凭据到期时清除保存记录，提示重新扫码；网络临时失败会保留记录供重试。保存失败会明确显示「重启后需重新扫码」，不会退回明文保存。目前加密存储支持 Windows；正常关闭服务不会使 B 站登录失效。

只向 B 站官方 API 发送账号会话 Cookie。不会读取现有浏览器或其他程序的 Cookie、密码。二维码密钥保留在服务端；浏览器只拿到当前二维码图像和一个临时的本地请求标识。如需手动清除记住的账号，可先停止服务，再删除上述加密文件。

账号接入用于获取首页个性化推荐，不是 B 站「精选」App 的同一条专属流，不导入关注与收藏。登录后同时用于获取账号有权播放的高清视频流。

### 画质

登录后使用页面内的 DASH 播放器，默认从 B 站实际返回的视频流中优先选择 1080P；视频下方显示真实解码尺寸，并提供可用画质菜单。切换画质会保留进度、播放/暂停状态与音量。当前支持 AVC 视频和 AAC 音频，最高普通 1080P，不提供会员权限解锁、试看片段扩展或 DRM 绕过。

本地服务使用当前账号向 B 站官方播放接口取流，仅转发返回的官方 CDN 片段，不保存视频文件。转发地址由服务端生成，前端不能指定任意 URL；片段接口校验本地会话令牌和来源，凭据不会发送给 CDN。DASH 库来自 npm 的 dashjs 5.2.1，随本地服务提供，不加载远程脚本。

遇到兼容问题可点「外链播放」，使用原来的官方嵌入播放器；未登录时也使用外链播放。外链播放器的画质由 B 站控制，服务端扫码状态不会注入其浏览器 Cookie。

### 亮度

视频下方的「亮度」滑块支持 30%～160%，100% 为原始亮度，点「还原」恢复到 100%。只调整视频区域的显示效果，便笺和页面按钮保持原样，不改变显示器亮度。数值保存在当前浏览器，下次打开、切换视频和切换画质时保持。

支持 BV 号、av 号，以及 `www.bilibili.com/video/...`、`m.bilibili.com/video/...` 和官方外链播放器链接。保留 `p`（分 P）和 `t`（起始秒数）；默认静音、关闭弹幕。手动粘贴的链接不会自动播放。b23.tv 短链需要先手动展开。账号、画质、地区和视频播放权限仍由 B 站决定。

不使用第三方解析服务。视频链接只在内存中保存，便笺会存入此浏览器的 localStorage。应用不记录访问日志；`.runtime/server.log` 只有本地服务的运行信息。账号、推荐与媒体接口需要本地会话令牌，并校验请求来源。看视频仍会向 B 站发送请求，收起画面不隐藏网络或设备管理记录。

## 检查

`node --test test/*.test.mjs` 的 19 项检查覆盖链接解析、嵌入参数、扫码状态转换、取消与过期、账号校验、签名测试向量、凭据不出服务端、跨站访问限制、媒体地址限制及片段转发，也覆盖 Windows 加密存储、恢复登录、失效清理和网络失败后的重试。已在 Codex 内置浏览器完成真实扫码登录、服务重启后自动恢复、个性化推荐读取和 1920 × 1080 高清播放验证；亮度数值在刷新和重启后保留，且只影响视频区域。
